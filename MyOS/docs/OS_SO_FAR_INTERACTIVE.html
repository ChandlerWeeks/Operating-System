A small RISC-V kernel that can inspect its machine.

This guide explains what MyOS does now and what the Memory Lab adds next. Use the controls to trace boot, convert addresses, model allocation, and inspect an Sv48 virtual address. The widgets are teaching models. They do not read, start, or change the kernel.

01 · Current behavior

What the active kernel does

Active

Boot and enter

Limine enters _start in supervisor mode with paging enabled. The entry code sets gp, calls main, then stops the hart if main returns.

Active

Print and diagnose

The kernel clears the terminal and sends text one byte at a time through the SBI debug-console call. debugln! adds source location information.

Active

Read ACPI tables

The kernel obtains the RSDP from Limine, finds its XSDT, walks the XSDT, and reads selected ACPI data. It reports PCI ECAM, timer, interrupt-controller, and UART information when found.

Active

Stop cleanly

After the diagnostic pass, the current main calls SBI shutdown. It is an inspection kernel. It does not yet enter a scheduler, serve user programs, or keep running.

Prepared, not active

CPU and lock support

riscv.rs contains CSR, TLB-flush, SATP, and PTE support. sync.rs contains a spin mutex and one-time initialization. main.rs does not yet include these modules.

Not complete

Dynamic memory

galloc.rs installs a global allocator hook, but alloc returns a null pointer and dealloc does nothing. The heap must not be used yet.

Active

Panic behavior

The panic handler prints a tagged message and source location when available. It then waits forever with wfi. It does not allocate memory during panic handling.

Configured platform

QEMU virt machine

The run configuration selects 128 MiB RAM, four harts, AIA with APLIC and IMSIC, ACPI, and an RV64 CPU with Sv48 and Svpbmt enabled. Configuration is not proof that the kernel has a driver for each device.

Firmware boundary

SBI services

The active path uses the debug console and system shutdown. The SBI module also contains routines for hart start, stop, status, suspend, reboot, and specification version, but current main does not call most of them.

Important boundary. The ACPI reader is work in progress. It identifies known table signatures and reads packed fields with unaligned reads. This guide does not claim checksum validation or complete ACPI support.

03 · Firmware data and hardware discovery

Limine supplies boot facts. ACPI describes the platform.

Limine requests in this kernel

The source requests an HHDM offset, a physical memory map, an RSDP address, kernel physical and virtual bases, BSP hart ID, stack size, command line, date, and Sv48 paging.

For RISC-V, the paging request requires Sv48 as the preferred, minimum, and maximum mode. Limine can therefore either provide Sv48 or fail the request.

ACPI walk

RSDP → XSDT → table physical address → HHDM virtual address. The RSD PTR signature identifies the RSDP. Despite their current Rust names, RsdtRawV1 and RsdtRawV2 model RSDP layouts; they are not RSDT tables.

Each XSDT entry is one 64-bit physical address. The code converts it with pa_to_va() before it reads the table.

Why packed ACPI fields need care

ACPI layouts use byte positions from a firmware format. Rust structures use repr(C, packed) for these layouts. A packed field may not meet its normal alignment. The reader copies fields with read_unaligned() instead of forming an aligned Rust reference to them.

04 · Kernel image and address spaces

The linker defines the image. Limine maps the loaded parts.

texttrampolinerodata + requestsdataBSS

Loaded segments

.text and .trampoline are read and execute. .rodata is read only and contains the retained Limine requests. .data is read and write.

BSS is different

.bss is page-aligned, NOLOAD, and PT_NULL. Its bytes are not loaded or mapped by Limine. The Memory Lab must map it, flush translations, then clear its exact byte range before Rust uses BSS data.

Address conversion model

This model follows the current helper rules. It uses sample kernel bases because a live Limine response exists only during boot.

HHDM

For normal RAM, pa_to_va() adds the Limine HHDM offset. The kernel uses this virtual address to access physical memory.

I/O range

For physical addresses below 0x8000_0000, pa_to_va() selects the I/O range that starts at 0xffff_beef_0000_0000.

Future heap range

The planned heap virtual range starts at 0xffff_cafe_0000_0000. The constant reserves an address; it does not create mappings.

06 · Allocation models

Pages provide backing memory. Heap chunks serve requests.

Free-list page allocator model

Two separate usable regions are shown. Each square is one 4 KiB page. The model allocates from a free list; it does not assume adjacent physical addresses.

Chunk heap allocator model

The future heap has one continuous virtual range. Its 1,024 backing pages can be physically separate. This smaller display uses 32 allocation units to show alignment and holes.

All usable regions

Add every Limine USABLE region. A misaligned edge must not make a partly valid page. A region smaller than 4 KiB adds no page.

Address rule

A free-list node lives in a free page. Use an HHDM virtual address to read or write it. Convert an allocated page address with va_to_pa() before placing its PPN in a PTE.

Heap rule

The page allocator supplies 1,024 backing pages. The page table maps them in order into one virtual heap range. The chunk allocator then serves size and alignment requests inside that range.

07 · Sv48 page tables

One virtual address selects four page-table entries.

Sv48 uses four 9-bit virtual page number fields and a 12-bit page offset. Each page table has 512 entries. An entry stores a physical page number and control bits.

Level 3Use VPN[3]. A valid branch entry points to the next table.
Level 2Use VPN[2]. A leaf here can map a huge page.
Level 1Use VPN[1]. A leaf here can map a superpage.
Level 0Use VPN[0]. A leaf here normally maps one 4 KiB page.
Map operation: the essential rules

Read SATP, extract the root physical page number, form its physical address, and convert it with pa_to_va() before dereference. During a walk, an invalid intermediate entry needs a newly allocated and cleared page-table page. Store that page’s physical PPN in a valid branch entry. A branch has no read, write, or execute bit. A leaf has the target physical PPN and requested access bits. Flush the affected translation after a change.

PTE permissions and memory type

Read, write, and execute are PTE bits. MemFlags in the planned lab describes the requested access and leaf size; it is not itself a PTE. Memory-mapped devices need the I/O PBMT value and must not receive execute permission.

08 · Required mappings after memory initialization

Map, flush, then use the memory.

BSS

Writable kernel state

Round BSS bytes up to pages. Map each BSS virtual page to its matching kernel-image physical backing page with read/write access. Flush the batch. Then clear the exact BSS byte range.

I/O

UART and RTC

Obtain UART physical address from SPCR. Map it only when SPCR reports system memory. Map the allowed RTC physical address 0x10_1000. Both use the I/O virtual range and I/O memory attribute.

Heap

Continuous virtual heap

Allocate exactly 1,024 page allocations. Map their physical pages in order starting at KERNEL_HEAP_ADDR, read/write. Flush. Then make the chunk allocator available to the global allocator.
